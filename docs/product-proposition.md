# 产品命题 — agent-work-room

> 规则：一页写完。写不进一页 = 还没想清楚。
> 用法：每个新功能立项前回读一遍；服务不了这一页的功能，砍。

## 1. 一句话命题

给同时订阅多个模型、独立做 side project 的开发者的一支AI 团队——多个 agent 在一个线程里协作，所有协作经历沉淀成用户画像与团队记忆，第二十天比第一天更懂你。

## 2. 用户（具体到一个人）

- 他是谁：软件开发者兼产品经理
- 他今天怎么干活：开三个终端，Claude架构、GPT审、Gemini设计、自己在中间复制粘贴，上下文全靠脑子记
- 他为什么会留下来：因为我想用一个工具来管理我的协作，而不是用三个终端来手动切换，人肉路由。

## 3. 问题（必须亲历过）

- 现状之痛：我需要手动路由我的协作，这很耗时，很难记住上下文，还会让我卷入细节考量当中。
- 为什么现有方案没解决好：大多数太重/面向通用场景；裸 CLI 无团队记忆。

## 4. 核心循环（产品的发动机）

用户说话 → @路由到对的 agent → agent 带着记忆干活 → 结果与纠正（"以后不要这样"）沉淀进记忆 → 画像更新 → 下次协作更准 → 用户更依赖。

自检：循环每转一圈，用户离开的成本是否变高？若否，循环设计有缺陷。

## 5. 为什么赢（点名对比）

- vs 裸用 Claude Code / Codex / Gemini：单 agent、无跨模型协作、无团队记忆，路由靠人肉。
- vs LangGraph / AutoGen：它们是给工程师的编排框架，我交付的是开箱即用的产品。
- 护城河声明：对接与路由会被拉平，画像/记忆随时间复利 → 矛头是支柱三，其余是承重墙。所有功能之争，用这一条裁决。

## 6. 非目标（v0 明确不做）

- 不做纯编排框架/SDK，做产品

## 7. 最小成功证明（可证伪）

- 检验点（4 周后）：我自己连续 30 天用它（而非裸 CLI）干真活，且画像里至少积累了 10 条真实纠正/偏好
- 杀死条件：若 4 周后我仍更愿意直接开 Claude Code，产品方向杀死，仓库降级为学习项目
